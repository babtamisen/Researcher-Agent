# Calculation and rendering workflow — candidate 0.3

Read this before numerical research. This adds voluntary tools, not an enforced delivery gate. Runtime access and the actual terminal reply must be evaluated.

1. Retrieve original evidence. Record source locator, period, unit, scale, original text/table location and definition for each quantity. Retain conflicting evidence; never adjust an input just to pass validation. Citation presence does not prove source support.
2. For supported calculations read scripts/CALCULATOR.md. Execute scripts/validate.py with one strict record on stdin. Keep exact input, exit code, stdout and separate evidence including the supplied claim's source. Use python3 with a 10-second subprocess timeout. A timeout, nonzero exit, empty/invalid response or status other than verified is failure. publication_authorized is ALWAYS false.
3. Claims in source documents/drafts must be preserved when auditing them; do not replace an incorrect claim with a newly computed answer to manufacture a pass. For a newly derived metric, record that claim as analyst-calculated, calculate a proposed answer with a deterministic tool, and then validate. This verifies consistency only, not independent truth.
4. Use the returned canonical result statement unchanged in the answer artifact. Attach the full real source locators and analyst-calculation attribution for derived metrics. Label the formula with its result unit; rate formulas return percentage points, using a numeric rate_percent variable (e.g. 5.8), NEVER a percentage literal divided by 100 again. Do not regenerate formulas from memory.
5. On failure emit an unable-to-verify statement with full evidence locators. Do not publish the rejected derived result, even as an 'implied' or 'withheld' value. Source inputs may be quoted explicitly as evidence. Fixes require new evidence or a documented extraction correction, retained with the failed original record.
6. Supported operations: USD EPS; strict reconciled USD net debt; annualize/deannualize quarterly rates. Other currencies, YoY, FCF and segment growth are not supported by this checker. Use another deterministic calculation with traceable evidence and label it 'outside prototype validation'; never imply whole-report validation. Withhold unresolved metrics. For Apple liquidity, do not invent a tolerance to make rounded figures reconcile: report the source's disclosed unrestricted liquidity and explain what cannot be validated.
7. Create report.json as exactly {"blocks":["paragraph including full citations", "next paragraph"]}. Include analysis and supported numerical statements together. Cite material claims at their point of use. Source locators must be full strings, not '#shares' shorthand, 'all sources', or generic descriptions.
8. Audit blocks for extraction fidelity, definitions, citations, contradictions and task word limit. Then execute scripts/render.py via stdin and save its stdout as report.md. Renderer checks shape only and joins blocks without rewriting; it does not grade arithmetic, citations or prose. Preserve hashes of records, report.json and report.md in private evaluation evidence.
9. The actual final response should reproduce report.md exactly, with no re-summary, extra commentary or citation deletion. This is a model instruction, NOT enforced preservation. Administrator must compare the actual terminal response with rendered output. A file artifact alone is not a passing delivered answer. Do not send or install anything externally.

Keep task artifacts private and outside Git. Do not read benchmark keys, previous answers, unrelated host files or private main memory.
