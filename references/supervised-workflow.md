# Supervised workflow — replaces v0.3 autonomous calculation instructions

STAGE 1: EXTRACTION
Read the assigned source documents and provide evidence.json as an artifact or response. Each evidence row contains row_id, full locator, original_label, exact excerpt, decimal-string value (when numeric), currency/unit, scale, reporting period/as-of date and definition notes. Keep revisions, conflicting figures and missing data explicit. Never normalize units manually where code can convert them. Provide proposed calculation mappings referencing row IDs, plus the research question and unresolved gaps. End with awaiting_administrator_review. No full briefing, investment conclusion or numerical metric approval at this stage.

For USD liquidity only, prepare adapter input as specified by tools/adapter/adapter.py: evidence rows have exactly row_id, locator, original_label, excerpt, value, currency, scale, as_of; mapping has gross, restricted, pledged, available, debt; supplied_claim has only row_id and places. No model-generated base-USD claim. Other evidence/definition notes live in separate artifacts, not extra adapter fields. If no supplied net-debt claim exists, do not invent one to satisfy this adapter. Administrator can calculate separately and label scope.

STAGE 2: ADMINISTRATOR REVIEW (not performed by researcher)
Administrator checks every material mapping against actual source excerpt/table, period, unit, definition and disjointness. Preserve the original extraction before corrections. Administrator runs applicable unchanged tools and independent calculations with a 10-second timeout, exact original receipts and exit codes. Passing code does not override unsupported source mappings. Strict calculator rejects rounded liquidity bridges: no silent tolerance or relabeling. Administrator returns an explicit review handoff listing approved/rejected claim IDs, source definitions, units, periods, calculated results/formulas, citations and permitted scope. Rejections are withheld. No handoff is a signature or enforceable platform permission.

STAGE 3: DRAFT
Only after that handoff, create report.json as {"blocks":["paragraph with complete citations", "next paragraph"]}. Use approved numerical statements; do not change precision, bases or units without returning for review. Source facts and analytical implications must be distinguished. Administrator-only tools are not instructions for the model to execute or simulate. Missing/rejected metrics are explicitly unavailable, not printed as implied values. Do not claim the entire report was validated. EPS/rates outside supported tools need administrator-reviewed calculation receipts too. Analysis must be consistent: higher QoQ GDP growth is acceleration on that measure, not 'not accelerating'; compare thesis invalidation conditions with current facts before calling them future risks.

STAGE 4: ADMINISTRATOR FINAL REVIEW/RENDER
Administrator checks final numbers, citations, source support, logic, requested word limit and claims of verification. Administrator renders report.json with tools/calculator/render.py. Researcher may return the reviewed report text without rewriting, but text identity is observational. Compare final output with rendered text allowing removal of exactly one final LF only. Any changed words/citations fail preservation. There is no automatic publication controller; no external delivery in acceptance.

This is a supervision experiment. No claim is made about autonomous cron readiness, enforced filesystem isolation, tool interception, source truth or investment safety. Keep tests and prior artifacts out of candidate runtime. No new research task is admitted until the current one is graded.
